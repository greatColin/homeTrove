# 需求文档：插件重跑支持范围选择

## 背景

当前「插件设置」页的「重跑」按钮会无差别地对整库所有文件重新入队，用户无法只针对部分文件重跑某个插件。同时「索引任务」页已具备实时进度展示能力，任务中心需求已被覆盖。

## 目标

让「插件设置」页的「重跑」按钮支持选择范围后再执行，降低重跑代价，提升操作可控性。

## EARS 需求

### 范围选择弹窗

WHEN 用户在插件设置页点击某个插件的「重跑」按钮，
THEN 系统应弹出一个范围选择对话框。

WHEN 范围选择对话框打开时，
THEN 系统应默认提供「全部文件」选项，并按该插件支持的媒体类型过滤可重跑文件。

WHEN 用户在范围选择对话框的搜索框中输入关键词时，
THEN 系统应实时按文件名/路径模糊匹配并返回候选文件列表。

WHEN 用户在候选文件列表中勾选若干文件时，
THEN 系统应记录所选文件 ID，并支持取消勾选。

WHEN 用户点击「确认重跑」时，
THEN 系统应仅对所选文件（或全部选项下的过滤结果）丢弃该插件的旧任务并重新入队，
AND 完成后给出已入队数量的提示。

### 后端接口

WHEN 前端请求 `/api/plugins/{plugin_id}/rerun-candidates` 并携带 `q`（可选）和 `media_type`（可选）参数时，
THEN 系统应返回符合条件的资产列表（含 ID、文件名、路径、媒体类型）。

WHEN 前端 POST `/api/plugins/{plugin_id}/rerun-selected` 并携带 `asset_ids` 列表时，
THEN 系统应对这些资产丢弃该插件已完成/失败的任务并重新入队，
AND 返回 `dropped` 和 `enqueued` 数量。

## 非功能性需求

- 候选列表接口需支持分页（limit/offset），默认每页 50 条。
- 搜索响应应在 300ms 内返回。
- 移动端弹窗应全屏或接近全屏，搜索框和多选列表适配小屏。

## 关联页面

- `/settings/plugins`：重跑按钮改为弹窗触发。
- `/jobs`：已有实时刷新，无需改动。
